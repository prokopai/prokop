### Added

- **Worktree setup from a repository file**: A repository can describe how a new managed worktree gets ready in `.prokop/worktree.json` at its root. When a worktree is created, ignored files such as `.env` are copied from the main checkout, directories such as `node_modules` are cloned without taking extra disk space, and env and template files are written with a port block reserved for that worktree (`{{port}}`, `{{port+1}}`) and a unique key for database or topic names (`{{key}}`). Every target has to be in `.gitignore`, so the worktree stays clean and can still be removed; a target that is not is refused with the path to add. The file is read from the main checkout and checked before the worktree is created, so a typo refuses creation with the line that is wrong. Each worktree reports its setup state and port block. Setup and teardown commands listed in the file are accepted but not run yet.
