### Added

- **Steer a running agent**: A message you send while an agent is working is now delivered into the running turn instead of waiting for the turn to end, and its bubble says "Steering" until the agent receives it. To keep the old behavior, set **Settings > Appearance > Messages sent while the agent works** to **Queue**; the choice is kept per device. A queued message has a **Steer** button, and pressing Enter in an empty message box steers the oldest queued message. Your message then appears in the conversation at the point the agent read it, and the rest of the reply answers it. Prokop agents receive it after their current tool step finishes. Claude Code receives it between tool calls. Codex receives it through its own steering request. If the turn ends first, or the agent cannot take it (Claude Code and Codex Goal runs, a stopped turn), the message stays in the queue and is sent after the turn like any queued message, so it is never lost. In Codex sessions, Undo and Fork work on whole turns: they are available after the reply to a steered message, not between the steered message and the reply before it.

- **Switch harness mid-conversation**: When Claude Code or Codex runs out of usage, pick a model from another harness (Prokop, Claude Code or Codex) in the session's model picker and keep working in the same session. Before, the harness was locked after the first message. The new harness starts its own fresh thread and gets a summary of the conversation in its instructions: the first request, the last six turns with each tool call on one line, and the session ID so it can look up earlier details with session search. Nothing from the earlier turns runs again. The conversation shows "Switched to Codex CLI · gpt-5" where the switch happened. Switching works while the session is idle, with no queued messages, pending approvals, running Goal or Compact. After a switch, Fork is unavailable, and Edit and Undo are unavailable in Claude Code and Codex. In Prokop they still work for turns after the switch.

- **Agents can show pages in their replies**: Prokop, Claude Code and Codex agents can show a chart, table, diagram or mockup as a page inside their reply, above the text. The page follows your light or dark theme, grows to fit its content, and opens in a new tab from its corner button. It runs sandboxed, with no access to Jean2's stored login or storage. This comes from a new built-in MCP entry, **Prokop Visuals**, which is on without any setup. Turn it off, or turn off its `render_html` tool, in MCP settings for all workspaces or for one. Subagents and learning reviews do not get it. A page can be up to 200 KB.

- **Diagrams and math in messages**: A ` ```mermaid ` block is drawn as a diagram once its closing fence arrives. Until then, and if the diagram has an error, it shows as code; a corner button switches between the diagram and its source. Math between `$$` signs, inline or on its own lines, and ` ```math ` blocks render with KaTeX. A single `$` stays plain text, so prices such as "$5 and $10" are not turned into math.

- **Reorder terminal tabs**: Drag a terminal tab to a new position, the same way you reorder dock tabs. The order is kept per workspace on this device, and new terminals open at the end.

### Fixed

- **Codex image generation no longer breaks the session**: When Codex generated an image larger than about 1.5 MB, Jean2 dropped its connection to Codex mid-turn, and the session stayed stuck on "The turn may have run; it will not be resent until reconciled". Codex sends the whole image in one message, and Jean2 refused messages over 2 MB; the limit is now 64 MB, and long messages are read in linear time. A generated image now shows inline under its row, outside the folded tool calls and in older turns too; click it to open it full size. Jean2 keeps its own copy with the session, so it stays after Codex cleans up its folder. If the image cannot be read, the row says where Codex saved it, and it says when the image limit was reached. Codex is also told that its images reach you this way: Codex hands the image to Jean2 rather than to the model, so before, the model saw an empty result and sometimes replied that it could not show the image.

- **Claude Code and Codex read their own skills without asking**: Reading a skill from `~/.claude/skills`, `~/.claude/plugins`, `~/.codex/skills` (including Codex's built-in `.system` skills), `~/.codex/plugins` or `~/.agents/skills` no longer asks for outside-workspace access. `CLAUDE_CONFIG_DIR` and `CODEX_HOME` are honored. Only reading is allowed: writing there still asks, and so does reading anything else in those homes, such as `~/.codex/auth.json`, settings, history or other sessions. A link inside a skill folder is judged by where it points.

- **Claude Code web results stay folded**: Claude Code's web search and web fetch rows now show one line ("Searched: …" or "Fetched: …", with the page size) instead of the full results as markdown under the row. The results are still in **Show raw data**, as with Prokop's own web fetch.

- **Opened attachments cannot run scripts**: An attached file opened from the conversation is now shown sandboxed, with no scripts and no access to Jean2's stored login. Before, an attached HTML page opened in a new tab ran as Jean2 and could read the API token. Images still show inline as before.

- **Following the conversation stays at the bottom**: While the view follows new output, it now stays at the bottom when you send a message, however long. Before, a long message or a large tool output could leave the view above the end without bringing it back. Sending could also make the conversation flick up for a moment when the message box shrank back, and each new line of a streamed reply showed briefly below the edge before the view caught up. Scrolling up still stops following right away.

- **Stop responds at once**: Pressing Stop now switches the session to idle right away: the Stop button turns back into Send, and the running markers in the sidebar, tabs, header and window title clear. Before, they stayed until the agent had fully shut down, which takes about 2 seconds for Claude Code. A message you send in that moment is queued and runs once the stopped turn has ended. It is never steered into the turn you stopped. If the server reports that nothing was stopped, the session shows as running again.

- **Terminal on phones**: The terminal sheet now stops above where the on-screen keyboard opens, so typing never hides the prompt, and with the keyboard up it fills the space above it. The tab row no longer stretches into an empty band. A key row under the terminal adds **^C** to stop a running process, plus **Esc**, **Tab** and arrow keys; tapping them does not open or close the keyboard.
